# Linux System Introspection


> 

| **Category** | **Mechanism** | **Description** | **Use** |
| --- | --- | --- | --- |
| **Kernel Introspection** | **eBPF / ftrace / perf** | Hooks into kernel functions or tracepoints to observe runtime behavior, system calls, and performance metrics. | Debugging, performance profiling, security monitoring, anomaly detection. |
| **Memory Introspection** | **/proc, /sys, /dev/mem, snapshots** | Access kernel and process memory structures via pseudo-filesystems or memory dumps. | Malware detection, forensic analysis, system auditing, monitoring. |
| **Hypervisor-based Introspection** | **KVM, Xen introspection** | Observe a Linux guest OS from a hypervisor, without affecting guest execution. | Security monitoring, rootkit detection, forensic investigation. |
| **System Call Monitoring** | **strace, auditd** | Intercepts and logs system calls made by processes. | Debugging, compliance auditing, intrusion detection. |
| **Log-based Introspection** | **syslog, journald, audit logs** | Analyze logs generated by OS services, kernel, and applications. | Security monitoring, troubleshooting, behavioral analysis. |
| **Filesystem / Process Inspection** | **ls, ps, lsof, inotify** | Inspect active processes, open files, and filesystem events. | System auditing, performance monitoring, incident response. |
| **Network Introspection** | **tcpdump, iptables, netfilter hooks** | Capture and analyze network traffic or kernel-level network events. | Security monitoring, intrusion detection, traffic analysis. |
| **Hardware-assisted Introspection** | **Intel PT, Intel VT-x, AMD-V** | Use CPU virtualization and tracing features to observe kernel or OS behavior from outside. | Secure monitoring, malware analysis, forensic investigation. |
