# x86

> x86 (also known as 80x86 or the 8086 family) i**s a family of complex instructio**n set computer (**CISC**) instruction set architectures  **(ISA)** initially developed by Intel based on the Intel 8086 microprocessor and its 8088 variant. The 8086 was introduced in 1978 as a fully 16-bit extension of Intel’s 8-bit 8080 microprocessors, with memory segmentation as a solution for addressing more memory than can be covered by a plain 16-bit address. The term “x86” came into being because the names of several successors to Intel’s 8086 processor end in “86”, including the 80186, 80286, 80386 and 80486 processors.
> 

> **x86** refers not only to the processor core, but to an entire **instruction set architecture (ISA) and platform ecosystem**, including execution modes, privilege levels, memory models, binary interfaces, firmware conventions, hardware subsystems, and legacy compatibility layers.
> 

## History

> Which is the **x86 timeline?**
> 

| **Version** | **Introduced** | **Description** |
| --- | --- | --- |
| **x86 (16-bit)** | 1978 | Introduced with the Intel 8086; 16-bit registers, 20-bit segmented addressing, real-mode execution model. Foundation of the entire x86 ISA family. |
| **x86 (32-bit)** | 1985 | 80386 architecture; added 32-bit registers, flat addressing mode, paging, protected mode, hardware task switching, and the modern x86 privilege model (rings). |
| **x86 (64-bit)** | 2003 (AMD64), 2004 (Intel 64) | 64-bit general-purpose registers, expanded register file, 64-bit virtual addressing, new calling conventions, and removal of segmentation (only FS/GS remain). |
| **MMX (Multimedia Extensions)** | 1997 | First SIMD extension; 64-bit MMX registers aliased over the x87 FPU state. Optimized for integer multimedia operations. |
| **SSE (Streaming SIMD Extensions)** | 1999 | Introduced 128-bit XMM registers separate from x87; SIMD floating-point support for vectorized FP math. |
| **SSE2** | 2001 | Extended SSE to support double-precision FP and full integer SIMD; effectively replaced MMX. |
| **SSE3** | 2004 | Added horizontal arithmetic ops and thread synchronization instructions (MONITOR/MWAIT). |
| **SSSE3** | 2006 | “Supplemental SSE3” with shuffle/absolute-value instructions important for crypto, codecs, and image processing. |
| **SSE4.1 & SSE4.2** | 2006–2008 | Added complex vector ops, dot-product, text-processing (PCMPSTRx), and CRC32 acceleration. |
| **AVX (Advanced Vector Extensions)** | 2011 | Introduced 256-bit YMM registers, 3-operand syntax, non-destructive ops, and VEX encoding. |
| **AVX2** | 2013 | Extended almost all integer SIMD to 256-bit; added gather loads and fused multiply-add (FMA). |
| **AVX-512** | 2016 | 512-bit ZMM registers, opmask registers (k0–k7), per-element masking, and massive expansion of SIMD ops. |
| **Intel VT-x** | 2005 | Hardware virtualization support: VMX root/non-root modes, EPT, VMCS, efficient trap handling. |
| **AMD-V** | 2006 | AMD’s hardware virtualization: SVM instructions, nested paging (NPT), improved hypervisor performance. |
| **Hyper-Threading (HTT)** | 2002 | Simultaneous Multithreading (SMT): two logical processors per physical core for higher utilization. |
| **Intel SpeedStep** | 2000 | Dynamic frequency/voltage scaling to reduce power consumption based on workload. |
| **Turbo Boost** | 2008 | Opportunistic frequency scaling above base clock when thermal/power limits allow. |

## x86 System Structure

> x86 is a *multi-layered ISA and platform architecture*, not just a CPU design. It defines the instruction set, memory and protection model, exception model, system interface, boot protocol, ABI contracts, and compatibility rules that all conforming processors and platforms must follow.
> 

| **Category** | **Part** | **Description** |
| --- | --- | --- |
| **Instruction Set Architecture (ISA)** | Instruction encodings | Binary opcode formats, prefixes, ModR/M, SIB, immediate fields. |
|  | Register model | General-purpose registers, segment registers, control registers, debug registers. |
|  | Addressing modes | Base+index+scale+disp, RIP-relative addressing, segment-based addressing. |
|  | Exceptions & faults | Architectural exception vectors, page fault semantics, general protection faults. |
|  | Privilege levels | Ring 0–3 privilege model defining access control and transitions. |
| **Execution Architecture** | Real Mode | 16-bit segmented execution model, BIOS-compatible environment. |
|  | Protected Mode | 32-bit model with segmentation, paging, privilege rules, IDT/GDT/LDT. |
|  | Virtual 8086 Mode | Hardware virtualization of 8086 under protected mode. |
|  | Long Mode | 64-bit execution mode, RIP-relative addressing, flat memory model. |
|  | System Management Mode (SMM) | Opaque privileged mode for firmware, ACPI, hardware control. |
| **Memory & Address Architecture** | Segmentation | Selector:offset model, hidden descriptor caches, legacy but architecturally required. |
|  | Paging | Multi-level page tables, 4K/2M/1G pages, PAE, NX, PCID. |
|  | Virtual memory | Architectural TLB behavior, page fault protocol. |
|  | Cache architecture | Architecturally visible cache behaviors (WC, WT, WB, UC, memory types). |
| **Interrupt & Exception Architecture** | IDT | Interrupt Descriptor Table structure and gate types. |
|  | Interrupt semantics | Priority rules, maskability, interrupt shadow, interrupt redirection. |
|  | APIC | Local APIC, I/O APIC, interrupt routing, x2APIC. |
| **System Architecture (Platform Architecture)** | Boot protocol | Reset vector, BIOS/UEFI startup contracts. |
|  | SMP startup | AP startup protocol using INIT-SIPI-SIPI sequence. |
|  | System calls | syscall/sysenter/sysret, legacy int 0x80 semantics. |
|  | ACPI & power states | S-states, C-states, architectural PM interfaces. |
| **Binary & ABI Ecosystem** | Calling conventions | System V ABI, Microsoft x64 ABI, register use, stack layout. |
|  | Object file formats | ELF and PE, relocation models, symbol resolution patterns. |
|  | Stack model | Stack pointer rules, red zone, shadow space. |
| **Compatibility Contract** | Legacy instructions | Full backwards compatibility to 8086, 286, 386, etc. |
|  | De-facto behaviors | Undocumented but required legacy behaviors preserved for compatibility. |
|  | Hardware interfaces | Requirements for BIOS/UEFI vendors, chipset manufacturers, OS designers. |

## **Microarchitecture**

> The x86 microarchitecture defines the **implementation-level organization** of an x86 processor, specifying how instructions defined by the ISA are executed in hardware. It includes the internal datapaths, pipelines, execution units, cache hierarchy, branch predictors, prefetchers, and other structures that collectively implement the ISA efficiently.
> 

| **Category** | **Part** | **Description** |
| --- | --- | --- |
| **Pipeline** | Stages | Sequence of processing steps for instruction execution (fetch, decode, execute, memory access, write-back). |
| **Execution Units** | ALU, FPU, SIMD | Hardware blocks performing arithmetic, logic, floating-point, and vector operations. |
| **Instruction Fetch & Decode** | Front-End | Logic that reads instructions from memory, handles prefixes, decodes to micro-operations. |
| **Micro-Operations (µOps)** | Translation | Many x86 instructions are broken into simpler µOps for internal execution. |
| **Out-of-Order Execution** | Scheduler / Reorder Buffer | Enables instructions to execute as resources become available, increasing throughput. |
| **Register Renaming** | Physical Registers | Maps logical registers to physical registers to avoid false data dependencies. |
| **Caches** | L1/L2/L3 | Multi-level caches to reduce memory latency; includes instruction and data caches. |
| **Branch Prediction** | Predictor / BTB | Predicts control flow to minimize pipeline stalls. |
| **Prefetching** | Instruction/Data | Mechanisms to bring data or instructions into caches before they are needed. |
| **Memory Subsystem** | TLB / Memory Controller | Translates virtual to physical addresses and manages memory access efficiently. |
| **Interconnects** | Bus / Ring / Mesh | Connects cores, caches, and other components for high-speed data transfer. |
| **Power & Clock Management** | P-states / C-states | Controls dynamic frequency scaling, sleep modes, and energy efficiency. |
| **Hardware Multithreading** | SMT / Hyper-Threading | Enables multiple logical threads per physical core to improve utilization. |

### Memory Alignment

> Memory alignment is the architectural constraint of allocating data at memory addresses that are integer multiples of the datum's size or the processor's natural word boundary, ensuring that memory accesses synchronize with the hardware's physical bus width and cache lines to minimize CPU fetch cycles and prevent hardware exceptions.
