# UX

> UX is the praxis of designing and optimizing interactions between humans and systems to enable effective, efficient, and satisfying goal achievement.
> 

> [Design – Specification Phase] How can we provide an interface for a set of underlying capabilities?
> 

> UX is a highly creative art of product conception and specification.
> 

> Note: Software is about providing concepts that enable users to accomplish specific tasks. The key is to understand: which tasks, to what end, and through which concepts or means.
> 

Guiding Questions:

- How do we **conceive** the system’s underlying capabilities in the first place? How to formulate and validate the problem being address? How to measure the valued provided to the user?
- How do we **communicate** those capabilities to the user?
- How can we design an interface that **maximizes the user’s ability** to leverage these capabilities?
- How do we **facilitate the discovery and effective use** of those capabilities?
- Evolution
    - How do we take the **user’s initial mental model**—no matter how naïve—and guide it toward a more powerful, accurate one?
    - How do we evolve the system itself so it **adapts to the user’s emerging needs**?

## Formulation

> Problem: People interact with digital and physical products, services, and systems, but their ability to achieve goals efficiently, effectively, and satisfactorily is hindered by the inherent complexity, ambiguity, or friction in these systems. Poorly designed interactions create cognitive load, frustration, errors, and abandonment, reducing value for both users and organizations.
> 

> UX:  UX solves the problem of translating complex system capabilities into intuitive, efficient, and satisfying human experiences, ensuring that users can achieve their goals with minimal friction and maximal confidence.
> 

> **UX is the praxis of giving soul to a system**: it transforms core capabilities—algorithms, services, and domain logic that, by themselves, are functionally complete but indifferent to human perception—into an **interaction layer** that embodies the **product’s identity, meaning, and value**. Through carefully designed interfaces, workflows, feedback mechanisms, and visual and behavioral cues, UX makes the system understandable, usable, and desirable, aligning it with human goals, context, and cognition. In this process, functionality becomes not just accessible but emotionally resonant, predictable, and trustworthy, allowing users to achieve their objectives efficiently while experiencing the product as coherent, recognizable, and engaging. In essence, UX is the art and science of translating raw computational power into a human-centered experience that feels alive, purposeful, and meaningful.
> 

> **UX has to convey** to the user the 'story' or behavior of the underlying soulless system.
> 

How can a system’s design align with human capabilities, needs, motivations, and context, so that users can accomplish their goals intuitively, reliably, and pleasantly, while minimizing errors, confusion, and wasted effort?

**Underlying Tensions UX Addresses:**

1. **Human vs. System Complexity:** Systems are inherently complex, but humans have cognitive and perceptual limits. UX mediates this gap.
2. **Goals vs. Friction:** Users have objectives; the system may unintentionally obstruct them. UX reduces friction and aligns the path to the goal.
3. **Function vs. Experience:** A system might be functionally complete but unpleasant or confusing to use. UX ensures functional success is paired with emotional and cognitive satisfaction.
4. **Predictability vs. Flexibility:** Users need predictable interactions but also freedom to explore. UX designs balance guidance and flexibility.

## Workflow

> What is the typical workflow that a UX practitioner follows?
> 

| **Phase** | **Description** | **Activities & Artifacts** |
| --- | --- | --- |
| **1. Research & Discovery** | Understand users, context, and business goals. | User interviews, surveys, ethnographic studies, competitive analysis, analytics review, personas, empathy maps. |
| **2. Define & Ideate** | Translate insights into user needs and design opportunities. | Problem statements, user stories, task flows, user journeys, brainstorming, feature prioritization. |
| **3. Information Architecture** | Organize content and functionality for clarity and usability. | Sitemaps, navigation flows, content hierarchies, labeling systems, taxonomies. |
| **4. Interaction & Visual Design** | Design how users interact with the system and how it looks. | Wireframes, mockups, prototypes (low/high fidelity), design systems, UI components, style guides. |
| **5. Prototype & Test** | Validate design decisions and identify usability issues early. | Interactive prototypes, usability testing (moderated/unmoderated), heuristic evaluations, cognitive walkthroughs, A/B testing. |
| **6. Iterate & Refine** | Improve design based on feedback and testing results. | Design revisions, updated prototypes, documentation of changes, alignment with stakeholders. |
| **7. Handoff & Implementation Support** | Communicate designs and specifications to development teams. | Annotated designs, UI specifications, component libraries, interaction guidelines, design tokens, accessibility notes. |
| **8. Monitor & Evaluate Post-Launch** | Observe user behavior and system performance to inform continuous improvement. | Analytics dashboards, user feedback, surveys, session recordings, performance metrics. |
| **9. Sustain & Evolve** | Continuously optimize the product experience over time. | Feature enhancements, UX improvements, accessibility updates, workflow optimizations, design system evolution. |

## Output Space

> Which are the outputs of the UX Process?
> 

| **Output Type** | **Description** | **Instance(s)** |
| --- | --- | --- |
| **User Research Artifacts** | Insights about users, their needs, goals, behaviors, and context. | Personas, user journeys, experience maps, empathy maps, task analyses, interview notes, survey reports. |
| **Requirements & Specifications** | Translating user insights into actionable system requirements. | User stories, use cases, functional requirements, accessibility requirements, interaction requirements. |
| **Information Architecture** | Structure and organization of information and content. | Sitemaps, content hierarchies, navigation flows, taxonomies, labeling systems. |
| **Interaction & Interface Designs** | Visual and behavioral representation of system interactions. | Wireframes, mockups, prototypes (low/high fidelity), interaction diagrams, design systems, component libraries. |
| **Usability & Evaluation Reports** | Evidence-based assessments of the system’s usability and effectiveness. | Usability test reports, heuristic evaluations, accessibility audits, A/B test results, analytics dashboards. |
| **Guidelines & Standards** | Design principles and best practices to guide implementation. | Style guides, pattern libraries, UX guidelines, accessibility standards (WCAG), design tokens. |
| **Metrics & KPIs** | Quantitative indicators of user experience quality. | Task success rates, error rates, completion times, user satisfaction scores, Net Promoter Score (NPS). |
| **Communication Artifacts** | Documentation to align teams and stakeholders. | UX strategy documents, stakeholder presentations, journey storytelling, annotated wireframes. |
| **Decision Support** | Insights for product strategy and prioritization. | Recommendations for feature prioritization, workflow optimization, or interaction improvements. |

### Adaptive Interface

> An interface that dynamically adjusts its structure, content, or behavior in response to the user’s context, capabilities, preferences, or system state.
> 

- How do we adapt the interface to the monitor while maintaining modularity?

| --- | --- | --- |

### Interaction Model

> **Note:** These are design interaction models, **not implementation mechanisms** such as micro-frontends.
> 

> They describe **how the workflow and workspace are organized**, how users interact with multiple tools, panels, and tasks, and how state is maintained.
> 

> Most real products use **hybrids** (e.g., Slack: primarily **SPA** with **Modal workflows** and **Command interaction**).
> 

> See https://nextapps-de.github.io/winbox/
> 

| **Model** | **Description** | **Evaluation** | **Case** |
| --- | --- | --- | --- |
| Page Navigation Model | Document-centric, page-to-page interaction; stateless; each page is independent. | Simple to implement; low cognitive load; not suitable for multi-tool workflows; state resets on navigation. | Traditional websites, blogs, Wikipedia. |
| Single-Page Application (SPA) Model | One shell app; views swap dynamically without full page reload; local state persists. | Smooth transitions; good for interactive apps; higher development complexity; initial load larger. | Gmail, Trello, Slack Web. |
| Multi-Document Interface (MDI)  (Workspace) (Multi-Pane Model) | Desktop-style workspace with multiple internal windows/panes; persistent state per pane. | High flexibility; supports multi-tasking; complex to develop; requires advanced state management. | VSCode Web, Figma, Notion. |
| Hub-and-Spoke Model | Central hub page with multiple independent sections (“spokes”); navigation flows from hub. | Clear hierarchy; easy entry point; can fragment workflows; limited parallelism. | Admin dashboards, mobile apps (Spotify, banking apps). |
| Step-by-Step Model (Wizard) (Task-Flow Model) | Sequential, guided task flows; each step depends on the previous. | Good for onboarding; reduces errors; rigid; interrupts multitasking. | Checkout processes, account setup, software installation wizards. |
| Tool-Based / Mode-Based Model | UI behavior changes according to selected tool or mode. | Efficient for expert workflows; can confuse novices; risk of mode errors. | Adobe Photoshop, Illustrator, CAD apps. |
| Object-Oriented UI (OOUX) | UI organized around objects and their relationships, not pages. | Makes complex systems understandable; improves discoverability; requires deep object modeling. | Trello, Airtable, GitHub Issues. |
| Command Interaction | Users trigger actions via searchable command interface. | Fast for power users; reduces menu complexity; requires learning shortcuts. | VSCode, Notion, Raycast, Linear. |
| Feed Model | Continuous, scrollable content stream; minimal navigation. | Simple browsing; addictive; weak multi-tasking support; low state persistence. | Twitter, Facebook, TikTok, Reddit. |
| Modal Workflow | Tasks occur in modals or overlays; main context preserved behind. | Focused; preserves context; can be disruptive if overused. | Mobile bottom sheets, confirmation dialogs, editing forms. |
| Conversational Model (Natural Language/Chatbot) | The primary interaction is through natural language (text or voice), where the system interprets user intent and responds. | Highly engaging; useful for guidance, support, or discovery; limited for complex multi-step tasks; learning curve for language input. | ChatGPT interface, Intercom, banking or travel chatbots. |
| Interface Agent Model | Users interact with a semi-autonomous agent that assists, suggests, or automates tasks. | Can improve efficiency and reduce cognitive load; may reduce transparency or control; users must trust the agent. | Microsoft Clippy (historic), virtual assistants, AI task agents (Notion AI, Copilot). |

### Evaluation

> How to evaluate a **UX**?
> 

| **Criteria** | **Metrics** | **Description** |
| --- | --- | --- |
| **Usability** | Task success rate, completion time, error rate, efficiency, navigation clarity | Measures how easily users can accomplish their goals using the system, including effectiveness, efficiency, and error rate. |
| **Learnability** | Time to proficiency, first-time task success, error rate for new users, number of help requests | Assesses how quickly and easily new users can understand and begin using the system correctly. |
| **Accessibility** | WCAG compliance score, screen reader compatibility, keyboard navigation success, color contrast ratio | Evaluates whether the system can be used by people with diverse abilities, including compliance with standards like WCAG. |
| **Satisfaction** | System Usability Scale (SUS), Net Promoter Score (NPS), user comfort rating, emotional response surveys | Captures users’ subjective perceptions and emotional responses, including comfort, enjoyment, and trust. |
| **Engagement** | Session duration, task frequency, interaction depth, return visits, feature usage | Measures the degree to which users are motivated, interested, and involved when interacting with the system. |
| **Cognitive Load** | NASA-TLX score, mental effort rating, number of steps per task, error frequency under stress | Assesses the mental effort required to use the system, aiming to minimize unnecessary complexity and confusion. |
| **Efficiency** | Task completion time, number of clicks/taps, time per action, resource consumption | Evaluates the speed and resource usage with which users can complete tasks, including clicks, time, and cognitive steps. |
| **Error Tolerance / Recovery** | Number of errors, severity of errors, recovery time, undo/redo usage | Measures how often users make mistakes, how severe they are, and how easily they can recover from them. |
| **Consistency** | UI pattern adherence, workflow predictability, visual style conformity, terminology uniformity | Checks that interaction patterns, visual cues, and behaviors are predictable across the system. |
| **Value Alignment** | Goal completion rate, task relevance, feature usage matching user needs, satisfaction alignment | Determines whether the UX supports user goals, expectations, and the overall purpose of the system. |
| **Behavioral Impact** | Adoption rate, retention rate, feature engagement, conversion rate | Evaluates whether UX leads to desired user behaviors, adoption, or retention. |
| **Observability / Feedback** | Visibility of system state, error message clarity, progress indicators, feedback response time | Measures how clearly the system communicates state, progress, and outcomes to the user. |
| **Aesthetic & Brand** | Visual appeal rating, brand consistency score, emotional resonance, design coherence | Evaluates how visually pleasing the interface is, how well it reflects brand identity, and the emotional impression it leaves on users. |
| **Brand Personality & Tone (Conceptual Identity) (Visual Identity)** | **Alignment with brand voice**, consistency of tone, visual identity coherence, emotional resonance | **Assesses whether the system** communicates a coherent brand personality and tone across visuals, copy, and interaction, reinforcing the conceptual identity. |
| **Trust & Credibility** | Perceived security, data privacy ratings, error transparency, user confidence rating | Measures users’ trust in the system, including data handling, transparency, and reliability. |
| **Emotional Impact** | Emotional valence, user delight score, frustration level, positive/negative sentiment | Evaluates how the system affects users emotionally, promoting positive experiences and minimizing negative reactions. |
| **Personalization / Adaptability** | Customization options used, adaptive content relevance, recommendation accuracy, user preferences satisfaction | Assesses how well the system can adapt to individual user needs, preferences, and behavior patterns. |
| **Social / Collaborative UX** | Shared task success rate, collaboration frequency, communication effectiveness, group satisfaction | Measures effectiveness and satisfaction when multiple users interact or collaborate through the system. |
| **Contextual Fit** | Task-context alignment, environment adaptability, device/context usage frequency | Evaluates whether the UX is effective in different environments, devices, and contexts of use. |
| **Error Prevention** | Frequency of preventable errors, proactive guidance, warnings and constraints effectiveness | Measures how well the system prevents errors before they occur, reducing user mistakes. |
| **Learned Efficiency / Expertise Development** | Improvement over repeated tasks, shortcut adoption, expert behavior metrics | Evaluates how the system supports users in becoming more efficient and proficient over time. |

### Validation

> How to validate a UX design? UX validation is **iterative, evidence-driven, and user-centered**. It’s not about confirming assumptions but uncovering real user behaviors, frustrations, and successes to guide design decisions.
> 

> Starting with evaluation criteria and success metrics, we choose suitable validation methods, gather and analyze data, make evidence-based decisions, and iterate on the design as needed to ensure usability and effectiveness.
> 

| **Method** | **Description** | **Note** | **Method Effectivity** | **Method Limits** |
| --- | --- | --- | --- | --- |
| **User Testing** | Observing real users interacting with prototypes or live systems. | Task completion observation, think-aloud sessions, usability tests. | Highly effective for usability, task success, error detection, and overall user experience. | Can be time-consuming and resource-intensive; limited sample size may not represent all users. |
| **Moderated Testing** | Users perform tasks while being observed by a facilitator. | Lab usability tests, in-person task sessions, guided remote tests. | Effective for uncovering usability issues, learning difficulties, and user frustration points. | Observer bias possible; artificial testing environment may affect user behavior. |
| **Unmoderated Testing** | Users complete tasks remotely without a facilitator, often using automated platforms. | Remote usability testing platforms, recorded sessions, click-tracking. | Effective for large-scale usability insights, efficiency metrics, and behavior patterns. | Limited qualitative insights; less control over testing conditions; cannot probe user reasoning deeply. |
| **Heuristic Evaluation** | Experts review the design against established usability principles. | Nielsen’s heuristics checklists, expert review reports. | Effective for early identification of usability and consistency issues without involving users. | Relies on expert judgment; may miss real user behavior issues; not a substitute for actual user testing. |
| **Cognitive Walkthroughs** | Experts simulate users’ tasks to identify potential confusion or friction. | Step-by-step task simulations, notes on predicted user errors. | Effective for evaluating learnability and task flow clarity. | Time-consuming; depends heavily on assumptions about user knowledge and behavior; may not capture emotional responses. |
| **A/B Testing** | Compare two or more variations of a design to measure which performs better on specific metrics. | Split-test dashboards, conversion rate comparisons, click-through rates. | Highly effective for measuring performance, engagement, and preference between alternatives. | Requires sufficient traffic for statistical significance; limited to measurable metrics; cannot explain *why* users prefer one option. |
| **Surveys & Feedback** | Collect subjective measures of satisfaction, perceived ease of use, and emotional response. | Post-task surveys, SUS, NPS surveys, open feedback forms. | Effective for capturing user satisfaction, perceived usability, and emotional reactions. | Subjective responses; may suffer from bias or low response rates; cannot capture actual behavior. |
| **Analytics Review** | Track user behavior in live systems to detect bottlenecks, drop-offs, or unexpected patterns. | Pageviews, click paths, drop-off points, session recordings. | Effective for understanding real-world usage, efficiency, and behavior trends at scale. | Cannot reveal why users behave a certain way; data may be noisy or incomplete; privacy concerns. |
| **Accessibility Testing** | Evaluate compliance with accessibility standards using automated tools and manual checks. | WCAG audits, screen reader testing, keyboard navigation checks, contrast evaluation. | Effective for ensuring inclusivity, compliance, and usability for users with diverse abilities. | Automated checks cannot detect all issues; manual testing requires expertise and can be time-consuming. |
| **Preference Testing** | Present multiple design alternatives to users and ask them to rank or rate them based on criteria like usability, clarity, aesthetics, or trustworthiness. | Wireframes, mockups, interactive prototypes; scoring sheets, surveys, heatmaps of choices. | Effective for assessing user preferences, perceived clarity, aesthetics, and desirability. | Reflects subjective preference rather than actual usability or performance; limited sample may bias results. |

## Theoretical Grounding

> What is the grounding of **UX Praxis**?
> 

| **Theoretical Domain** | **Premise** | **Implication for UX Praxis** |
| --- | --- | --- |
| **Human-Centered Design (HCD)** | Systems must be designed around human needs, capabilities, and limitations. | Design decisions are informed by human cognition, perception, and behavior to reduce cognitive load and enhance usability. |
| **Cognitive Science** | Understanding how humans perceive, process, and act on information allows systems to align with mental models. | Interfaces are structured to match memory, attention, and problem-solving patterns, making them predictable, learnable, and efficient. |
| **Interaction Design & Semiotics** | Interfaces are communicative artifacts conveying meaning through signs, symbols, and behaviors. | Interaction flows, feedback, and affordances are designed to make system logic legible and meaningful. |
| **Systems Thinking** | UX exists within a broader socio-technical system, including user goals, organizational context, and technological constraints. | Design considers emergent behaviors, context-dependent use, and ecosystem effects to create robust and coherent solutions. |
| **Experience & Emotional Design** | Systems evoke emotions, trust, and engagement beyond pure usability. | UX praxis deliberately crafts satisfaction, delight, and brand identity through visual design, micro-interactions, and consistent experience. |
| **Iterative & Evidence-Based Methodology** | Human behavior is complex and unpredictable. | Design is validated and optimized through iterative prototyping, testing, and data-driven refinement. |

### Biological Grounding

> Which are the biological facts that should ground UX?
> 

| **Biological Fact** | **Description** |
| --- | --- |
| **Limited Visual Acuity** | Users cannot reliably read small fonts, low contrast text, or densely packed UI elements. |
| **Weak Peripheral Vision** | Important actions must appear near the central visual field; edges are for low-priority content. |
| **High Motion Sensitivity** | Unnecessary animation distracts and increases cognitive load; motion should signal meaning. |
| **Motor Precision Limits** | Small or tightly packed targets increase error rate; users vary widely in precision. |
| **Fitts’ Law (Movement Time)** | Reaching a target depends on size and distance; larger/closer targets improve usability. |
| **Motor Fatigue** | Repeated fine movements (e.g., precise clicking, small touch targets) create strain. |
| **Energy Constraints of the Brain** | The brain conserves effort; unclear interactions increase metabolic load and reduce engagement. |
| **Stress Response** | Ambiguity, overload, and uncertainty trigger physiological stress, harming performance. |
| **Sensory Filtering** | Noise gets filtered out automatically; UI signals must be strong and distinguishable. |
| **Reaction Time (~200 ms)** | Feedback slower than ~200 ms feels broken; faster feels instant and responsive. |
| **Ergonomic Limits** | UI must respect natural ranges of eye, head, and hand movement to avoid strain. |

### Cognitive Grounding

> Which are the Cognitive facts that should ground UX?
> 

| **Cognitive Fact** | **Description** |
| --- | --- |
| **Mental Models** | Users act based on perceived system structure; UX must shape accurate, stable conceptual models. |
| **Limited Working Memory (~4 items)** | Users cannot juggle long instructions or multi-step holds; interfaces must reduce memory burden. |
| **Cognitive Load Theory** | Minimize extraneous load, respect intrinsic load, and support learning (germane load). |
| **Pattern Recognition Dominance** | Consistency enables fast recognition; inconsistency forces slow interpretation. |
| **Limited Attention** | Attention is scarce, serial, and easily lost; UX must minimize context switching. |
| **Predictive Cognition** | Users expect predictable flows; surprises or inconsistent rules cause confusion. |
| **Error is Normal** | Errors naturally occur; UX must provide prevention, detection, and recovery pathways. |
| **Learning Through Scaffolding** | Interfaces must evolve in complexity and reveal features progressively. |
| **Affordances & Signifiers** | Users rely on cues to understand possible actions; UI must visually indicate affordances. |
| **Dual Processing (System 1 / System 2)** | Routine actions should rely on fast, automatic cognition; complex tasks require deliberate steps. |
