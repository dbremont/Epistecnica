# Docker Compose

- Related Virtualization: Conceptual Model: [Docker](note.html?n=technica/computation/platform/virtualization/virtualization-conceptual-model/docker.md)

> It appears that you might be referring to Docker Compose, which is a tool used for defining and running multi-container Docker applications. Docker Compose uses a YAML file called a “docker-compose.yml” file to specify the configuration of the services, networks, and volumes that make up your application stack.

Here’s a breakdown of the key components and concepts in a Docker Compose file:

- `version`: Specifies the version of the Docker Compose file format being used. The format may change with different Docker Compose releases.
- `services`: Defines the services that make up your application. Each service is a containerized component of your application, and you can specify various settings for each service.
- `image`: Specifies the Docker image to use for the service, including the image name and optionally a tag.
- `container_name`: (Optional) Assigns a custom name to the container. If not specified, Docker Compose will generate a name based on the project name and service name.
- `ports`: (Optional) Maps ports from the host to the container, allowing you to expose services externally.
- `volumes`: (Optional) Specifies volume mappings for data persistence between the host and the container.
- `environment`: (Optional) Sets environment variables within the container.
- `networks`: (Optional) Defines the networks that services should be connected to. You can specify custom networks or use the default bridge network.
- `networks`, `volumes`, and `configs`: These sections allow you to define networks, volumes, and configurations that can be used by the services in your Compose file.

## Useful Commands

**Docker Compose** provides a set of commands that you can use to manage your multi-container **Docker** applications defined in a `docker-compose.yml` file. Here are some of the main **Docker Compose** commands:

1. **docker-compose up**: This command is used to start your Docker Compose application. It will create and start containers for all services defined in your `docker-compose.yml` file. By default, it runs in the foreground and displays logs. You can use the `d` flag to run it in detached mode (in the background).
    
    ```bash
    docker-compose up
    ```
    
    or
    
    ```bash
    docker-compose up -d
    ```
    
2. **docker-compose down**: This command stops and removes all containers, networks, and volumes defined in your `docker-compose.yml` file. It effectively shuts down your Compose application.
    
    ```bash
    docker-compose down
    ```
    
3. **docker-compose ps**: This command displays the status of containers that are part of your Docker Compose application, showing information such as container names, IDs, and their current status (e.g., running, exited).
    
    ```bash
    docker-compose ps
    ```
    
4. **docker-compose logs**: Use this command to view the logs generated by your Compose services. You can specify a specific service to view its logs or use the `-follow` flag to continuously stream the logs.
    
    ```bash
    docker-compose logs
    ```
    
    or
    
    ```bash
    docker-compose logs -f
    ```
    
5. **docker-compose exec**: This command allows you to run commands inside a running container. You specify the service name and the command to run.
    
    ```bash
    docker-compose exec service_name command
    ```
    
    For example, to open a shell inside a container:
    
    ```bash
    docker-compose exec web /bin/bash
    ```
    
6. **docker-compose build**: Use this command to rebuild Docker images for your services, which can be useful if you’ve made changes to your application or Dockerfiles and need to update the images.
    
    ```bash
    docker-compose build
    ```
    
7. **docker-compose restart**: This command restarts one or more services in your Docker Compose application.
    
    ```bash
    docker-compose restart service_name
    ```
    
8. **docker-compose pause** and **docker-compose unpause**: These commands allow you to pause and unpause services, respectively. Pausing a service temporarily stops its containers without removing them.
    
    ```bash
    docker-compose pause service_name
    ```
    
    ```bash
    docker-compose unpause service_name
    ```
