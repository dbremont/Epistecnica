# C++

- [ELF (Executable and Linkable Format)](note.html?n=technica/computation/language-system/conceptual-model-language-system/elf-executable-and-linkable-format.md)

> **C++** is a statically typed, multi-paradigm systems programming language that unifies low-level memory control with high-level abstraction mechanisms. It implements the imperative and procedural computational models natively, supports object-oriented programming with classes, inheritance, polymorphism, and encapsulation, and enables generic programming through templates and compile-time metaprogramming. Its execution model follows a close-to-hardware memory model with deterministic object lifetimes governed by RAII (Resource Acquisition Is Initialization) and explicit control over stack and heap allocation, while also providing a modular compilation model via header inclusion and namespaces. C++ supports fine-grained concurrency with threads, atomic operations, and memory models conforming to the C++ memory model, alongside advanced features such as coroutines, constexpr evaluation, and template instantiation mechanisms. Its type system is nominal and static but allows type deduction (auto, decltype), overloading, and SFINAE-based specialization, making it suitable for high-performance, low-latency applications that require deterministic resource management, extensive compile-time computation, and close mapping to underlying hardware architectures.
>

> The **Language System Interface** encompasses the collection of mechanisms, APIs, and tooling hooks that enable interaction with both the **compile-time** and **runtime** aspects of a programming language system. ### **What is name mangling in the context of C++ compilation and linking?**

> Name mangling is a compiler-driven process that encodes function, class, and namespace identifiers—along with their scope, parameter types, and template specializations—into a unique, low-level symbol name during compilation.
> 

> This transformation adheres to a platform-specific ABI (e.g., the Itanium ABI for Unix-like systems or Microsoft's ABI for Windows) to ensure unambiguous linkage, support function overloading, enforce namespace isolation, and enable runtime features like exception handling and **RTTI (Run-Time Type Information)**.
> 

> The mangled name incorporates metadata such as argument types (for function signature disambiguation), class hierarchies (for virtual method dispatch), and linkage specifications (e.g., `extern "C"`), while resolving ambiguities that arise from C++'s complex grammar (e.g., template instantiations, const/volatile qualifiers).
> 

> **Demangling** reverses this process for human-readable diagnostics (e.g., in debuggers or `nm`/`c++filt` output).
> 

**\Key Technical Aspects:**

1. **ABI Compliance**: Follows platform-specific rules (e.g., `_Z` prefix in Itanium, `?` in Microsoft).
2. **Overloading Support**: Encodes parameter types (e.g., `i` for `int`, `Pc` for `char*`).
3. **Scope Resolution**: Nests names (e.g., `N1A3BEE` for `A::B`).
4. **Virtual Table Integration**: Mangling vtables (e.g., `_ZTV`) and RTTI (`_ZTI`) symbols.
5. **Linker Interaction**: Ensures symbols are unique across translation units while preserving ODR (One Definition Rule).

Example:

- Function: `void Foo::bar(int, char*)` → `_ZN3Foo3barEiPc` (Itanium).
- VTable: `Base` → `_ZTV4Base`.

### How to demangle C++ symbols in an ELF executable or shared library?

```bash
nm -C your_executable_or_library.so
nm your_executable | grep _ZTV | c++filt
objdump -d -C your_executable # -C: Demangles symbols in assembly output.
objdump -T your_library.so | c++filt # Demangle Dynamic Symbols (for Shared Libraries)
readelf -s your_executable | c++filt
nm --no-demangle your_executable | awk '{print $3}' | c++filt
```
