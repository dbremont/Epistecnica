# Epistemic Tool Template

**Contains:** [General Topic Note Template](/view.html?p=notes/miscellanea/personal/general-topic-note-template.md)

> An **epistemic tool** is any technique, method, or formal mechanism used by an observer to construct, represent, and validate descriptions of reality.
> 

> An epistemic artifact is defined by its **functional role in encoding and enabling reasoning about affirmations of reality (proposition, probability distribution, constraint, etc)**, not by its material or representational substrate.
> 

> Which classes of tools cannot be adequately captured by this schema? (e.g., heuristic, tacit, non-formalizable tools)
> 

> Which dimensions are intentionally excluded? (e.g., sociological context, implementation details)
> 

## Index

## Identity

- **Name**
- **Type**
    - In which position of the global epistemic toolbox does it belongs to?
    - (e.g., inferential, generative, compressive, diagnostic, optimization-based)
- **One-line Summary**
    - Minimal functional description: *what transformation it performs*

## Formal Characterization

- **Input Space (Epistemic State)**
    - What is the structure of the input? (dataset, prior, signal, constraints…)
- **Output Space (Epistemic Artifact)**
    - What is produced? (posterior distribution, embedding, estimate, decision rule…)
- **Transformation**
    - Explicit mapping: $\mathcal{T}: \mathcal{E}{in} \rightarrow \mathcal{E}{out}$
- **Assumptions / Preconditions**
    - Statistical, structural, or ontological assumptions required for validity

## Epistemic Role

- **Function**
    - What epistemic gap does this tool resolve?
        - (uncertainty reduction, structure discovery, prediction, compression…)
- **Preservation Profile**
    - Which invariants are preserved?
        
        (e.g., expectation, topology, causal structure)
        
- **Destruction / Loss Profile**
    - Which information is irreversibly discarded?

## Mechanism

> How does it fulfill the role?
> 
- **Operational Structure**
    - Stepwise or functional decomposition of the mechanism
- **Constituent Components**
    - Sub-tools or primitives it depends on
- **Dependencies**
    - External epistemic tools or artifacts required

## Output Artifact

- **Artifact Type**
    - (probability distribution, scalar estimate, latent representation…)
- **Interpretability**
    - How should the output be read as a claim about reality?
- **Inference Affordances**
    - What operations are enabled on the artifact?
        
        (prediction, comparison, decision-making…)
        

## Validation

- **Correctness Criteria**
    - Formal tests or theorems (e.g., consistency, unbiasedness, convergence)
- **Empirical Validation**
    - Observable checks (e.g., residuals, calibration, backtesting)
- **Failure Modes**
    - Conditions under which the tool produces misleading artifacts

## Scope & Limits

- **Scope of Applicability**
    - Domains where the tool is valid
- **Limitations**
    - Structural limits (not just practical ones)
- **Robustness**
    - Behavior under assumption violations

## Cognitive Friction

- Which misunderstandings systematically distort correct usage?
    - Confusion between artifact and reality
    - Misinterpretation of assumptions as facts
    - Overextension beyond scope
    - Treating outputs as invariant under transformation changes

## Comparative Position

- **Equivalent / Related Tools**
- **When to Prefer / Avoid**
- **Trade-offs**
    - (bias vs variance, interpretability vs performance, etc.)

## Specifics

- Which affirmation about the underlying reality flux does it preserves? Which does it destroy?
- …

## ❓ QA

- Targeted diagnostic questions:
    - What happens if assumptions are violated?
    - What invariant does this tool rely on most critically?
    - Can two different tools produce indistinguishable artifacts?
