## Identity Model

> An identity model is a set of rules and concepts that define how users are identified and authenticated in a system.

It typically includes information about the following:

- **Unique identifiers:** A unique identifier is a string of characters that uniquely identifies a user. This identifier is typically used to authenticate users when they log in to a system.
- **Credentials:** Credentials are pieces of information that users use to prove their identity to a system. This could include passwords, security questions, or biometric data.
- **Claims:** Claims are statements about a user that are made by a trusted source. Claims can be used to make authorization decisions.

## User Identity

> Which mechanism - to identify the user and enable authentication exists?

| Category | Method | Description |
| --- | --- | --- |
| **Knowledge-Based** | Password | A user-supplied secret string that is compared against a stored cryptographic hash. |
|  | Passphrase | A longer, word-and-symbol-based version of a password for added entropy. |
|  | Knowledge-Based Authentication (KBA) | Broader category that includes pre-registered or dynamic life-history questions. |
|  | Security Questions | Personal questions registered during setup; answers are verified at login. |
|  | PIN | A short numeric code, usually combined with another factor (e.g., smart card). |
| **Multi-factor (MFA)** | Multi-Factor Authentication | Combines two or more independent factors (e.g., password + SMS code) during login. |
|  | One-Time Password (OTP) | A time- or event-limited code generated by hardware token, app, or SMS. |
| **Token-based** | Hardware Token | Small physical device that displays or transmits time-based OTPs. |
|  | Access Token | Short-lived credential issued by a server after initial login; used for session/authorization. |
| **Certificate** | Smart Card | Tamper-resistant card with embedded chip that stores cryptographic keys or certificates. |
|  | Client Certificate | Digital X.509 certificate installed on the user’s device to prove identity. |
| Social / External | Social Login | Reuses existing credentials from an OAuth provider (e.g., Google, Facebook) to log in. |
| **Out-of-band** | Email Verification | A code or link sent to the user’s registered email address. |
|  | SMS Verification | A code sent via text message to the user’s registered phone number. |
|  | Push Notification | Mobile app notification prompting the user to approve or deny a login attempt. |
| **Biometric** | Fingerprint Scan | Captures and matches unique ridge and valley patterns on a fingertip. |
|  | Face Recognition | Analyzes facial landmarks and geometry for identity matching. |
|  | Iris Scan | Maps the colored ring around the pupil; highly unique and stable. |
|  | Retina Scan | Images the pattern of retinal blood vessels at the back of the eye. |
|  | Voice Recognition | Compares vocal characteristics such as pitch, cadence, and formants. |
|  | Palm Vein | Infrared scan of vein patterns beneath the skin of the palm. |
|  | Ear Shape Recognition | Matches ear contours and geometry captured via camera or sensor. |
|  | Gait Recognition | Identifies individuals by the unique way they walk, often via video or wearables. |
|  | Heartbeat Authentication | Uses electrocardiogram (ECG) patterns or PPG signals for identity. |
|  | Brainwave Authentication | EEG-based identification using distinctive neural signal patterns. |
|  | Keystroke Dynamics | Measures typing rhythm, dwell time, and flight time. |
|  | Behavioral Biometrics | Continuous analysis of mouse paths, scroll speed, touchscreen pressure, etc. |
|  | Lip Motion Authentication | Tracks lip movement during speech for unique motion signatures. |
|  | Body Odor Analysis | Chemical sensor array detects volatile compounds unique to an individual. |
|  | Skin Texture Recognition | High-resolution imaging of pores, lines, and skin micro-features. |
| **Pattern-based** | Pattern Lock | User traces a secret path on a 3×3 (or larger) grid of dots. |
| **Location-based** | Location Verification | GPS/Wi-Fi triangulation to ensure login originates from an expected geolocation. |
| **Device-based** | Device Verification | Stores device fingerprints (OS, browser, MAC address) to recognize trusted hardware. |
| **Implantable** | Microchip Implant | NFC/RFID chip embedded under the skin for tap-to-authenticate scenarios. |
| **DNA** | DNA-Based Authentication | Uses an individual’s unique DNA profile; primarily theoretical and privacy-sensitive. |
| Public-Key | Passkey (FIDO2/WebAuthn) | Passwordless authentication using a device-held private key and server-held public key. |
| Public-Key | Security Key (FIDO/U2F) | External USB, NFC, or Bluetooth authenticator that performs cryptographic authentication. |
| Public-Key | SSH Public-Key Authentication | User proves possession of a private key corresponding to a registered public key. |
| Certificate | PIV/CAC Card | Government and enterprise smart cards containing identity certificates. |
| Device-Based | Platform Authenticator | Built-in authenticator such as Windows Hello, Apple Secure Enclave, or Android Keystore. |
| Possession-Based | Recovery Codes | Pre-generated one-time backup codes used when the primary authenticator is unavailable. |
| Network-Based | Kerberos | Ticket-based authentication protocol using a trusted Key Distribution Center. |
| Federated Identity | OpenID Connect (OIDC) | Authentication protocol built on OAuth 2.0. |
| Federated Identity | SAML | XML-based enterprise single sign-on protocol. |
| Continuous Authentication | Continuous Authentication | Continuously verifies identity throughout the session using behavioral or contextual signals. |
| Risk-Based | Adaptive Authentication | Adjusts authentication requirements based on risk, context, and user behavior. |

## HTTP Authentication

> Authentication models are frameworks or systems that define how users prove their identity to gain access to resources or services in a secure and controlled manner.

| Category | Method | Description | Security Level | Use Case / Notes |
| --- | --- | --- | --- | --- |
| Basic | `Authorization: Basic` | Sends base64-encoded `username:password` in header. | 🔓 Insecure without HTTPS | Simple; **always require TLS**. |
| Basic | Digest | Hashes credentials with a server-provided nonce. | ⚠️ Deprecated | Safer than Basic, but rarely used today. |
| Token-based | Bearer Token | `Authorization: Bearer <token>` — opaque or JWT. | ✅ Secure with HTTPS | Standard for OAuth2 / OIDC. |
| Token-based | JWT | Self-contained, signed tokens with claims. | ✅ Secure with validation | Stateless, supports expiry & scopes. |
| Token-based | API Key | `Authorization: Api-Key <key>` or custom header. | ⚠️ Risky if static | Rotate often; restrict scope. |
| OAuth2 / OIDC | Access Token | Token issued via OAuth2 flow (e.g., Auth Code). | ✅ Modern & robust | Delegated authorization. |
| OAuth2 / OIDC | ID Token | JWT from OpenID Connect with user claims. | ✅ Identity assurance | SSO & session establishment. |
| Mutual TLS | Client Certificate | X.509 certificate exchanged during TLS handshake. | 🔐 Very secure | Enterprise & IoT device auth. |
| Cookie | Session Cookie | Server-side session ID stored in a browser cookie. | ✅ Secure with HTTPS | Traditional web apps. |
| Cookie | Signed Cookie (JWT) | JWT stored in cookie; no server-side state. | ✅ Stateless | Modern SPA / API hybrids. |
| Platform-specific | Hawk / HMAC | MAC-signed request headers. | ⚠️ Niche | Internal APIs (Mozilla Hawk). |
| Platform-specific | AWS Signature V4 | HMAC-signed headers for AWS APIs. | 🔐 High security | Tamper- & replay-resistant. |
| Passwordless | WebAuthn / FIDO2 | Public-key, biometric or device-bound login. | 🔐 Phishing-resistant | Modern browsers & OS. |
| Passwordless | Magic Link | Email link with short-lived token. | ✅ With controls | Low-friction SaaS onboarding. |
| Passwordless | OTP | Temporary code via email, SMS, or TOTP app. | ✅ With rate-limiting | MFA step-up or fallback. |
| … | `WWW-Authenticate` | The HTTP WWW-Authenticate response header defines the HTTP authentication methods (“challenges”) that might be used to gain access to a specific resource. |  |  |
