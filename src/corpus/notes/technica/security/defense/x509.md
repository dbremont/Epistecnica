# X.509

> Related: [Cryptographic Data](/view.html?p=notes/technica/security/defense/cryptographic-data.md)

> **X.509** is a **standard for public key certificates** defined by the **ITU-T (International Telecommunication Union – Telecommunication Standardization Sector)**. It specifies the **format, structure, and validation rules** for digital certificates used in **Public Key Infrastructure (PKI)**.

## Structure

> What’s the structure of **`X.509`**?

```bash
Certificate
 ├─ tbsCertificate (to-be-signed)
 ├─ signatureAlgorithm
 └─ signatureValue
```

### tbsCertificate

| **Field** | **Description** |
| --- | --- |
| **Version** | Version of X.509 (v1, v2, v3). Usually v3 today. |
| **Serial Number** | Unique number assigned by the CA to identify the certificate. |
| **Signature Algorithm** | Algorithm used by the CA to sign this certificate (e.g., SHA256-RSA). |
| **Issuer** | Name of the CA issuing the certificate (Distinguished Name, e.g., CN, O, C). |
| **Validity Period** | `Not Before` and `Not After` dates, specifying the certificate’s lifetime. |
| **Subject** | Identity of the entity the certificate is issued to (domain, organization, user). |
| **Subject Public Key Info** | Contains the **public key** and its algorithm (RSA, ECDSA, etc.). |
| **Issuer Unique ID** (optional) | v2/v3 field for unique identification of the issuer. |
| **Subject Unique ID** (optional) | v2/v3 field for unique identification of the subject. |
| **Extensions** (v3) | Optional fields for additional constraints, policies, or metadata, e.g.: • Key Usage (signing, encryption, etc.)• Extended Key Usage (server auth, client auth)• Subject Alternative Name (SAN, e.g., multiple domains)• CRL Distribution Points (revocation info)• Basic Constraints (CA=true/false) |

### **signatureAlgorithm**

> Indicates the **algorithm used by the CA** to sign the certificate.

### **signatureValue**

> The **digital signature** produced by the CA over the `tbsCertificate`.

### Visual Representation

```bash
Certificate
├─ tbsCertificate
│   ├─ Version
│   ├─ Serial Number
│   ├─ Signature Algorithm
│   ├─ Issuer

│   └─ (Optional) Extensions

```

## Encoding

| **Encoding** | **Description** | **Extension(s)** | **Usage** |
| --- | --- | --- | --- |
| **DER (Distinguished Encoding Rules)** | Binary ASN.1 format. Compact, machine-readable. | `.der`, `.cer` (sometimes) | Used in Windows, Java keystores, and some networking applications. |
| **PEM (Privacy-Enhanced Mail)** | Base64 encoding of DER with header/footer delimiters: `-----BEGIN CERTIFICATE-----` … `-----END CERTIFICATE-----` | `.pem`, `.crt`, `.cer` | Common in Linux/Unix systems, OpenSSL, Apache, Nginx. Easy to view/edit in text editors. |
| **PKCS#12 / PFX** | Binary format that can bundle a certificate, its private key, and optionally the certificate chain. Usually password-protected. | `.p12`, `.pfx` | Windows import/export, IIS, software requiring both key + cert. |
| **PKCS#7 / P7B** | Binary or Base64 format that contains certificate(s) and optional chain, but **no private key**. Often used to distribute CA chains. | `.p7b`, `.p7c` | Importing certificate chains into Windows, Java, or email clients. |
