# Characterization System

Related Glossarium: Characterization, Characteristic, Property, Dimension

> A **characterization system** is a finite, reusable apparatus that assigns any instance of a domain a comparable profile: a fixed set of **dimensions**, each with a closed set of **categories or values**, plus explicit **mapping rules** that determine which value applies to a given instance.

A single **characterization** identifies one object ("P is necessary and sufficient for X"). A characterization system lifts this to a population: every instance gets one value per dimension, so two instances can be compared dimension by dimension.

## Components

- **Dimensions**: the aspects along which instances are described (e.g. governance arrangement, leadership form, operational deployment). Each dimension must be independent enough to avoid double-counting. See [Dimension](index.html?t=dimension).
- **Categories / values**: the allowed answers per dimension. They must be mutually exclusive and jointly cover the observed cases.
- **Mapping rules**: how evidence maps to a category (what counts as "board-governed", what counts as "functional"). Without rules the system is a vocabulary, not a system.
- **Comparability condition**: two instances characterized with the same version of the system must be directly comparable; changing dimensions or categories creates a new version.

## What it is not

- **Not a taxonomy**: a [Taxonomia](index.html?t=taxonomia) classifies by shared properties; a characterization system profiles across several independent dimensions at once.
- **Not a model**: a [Model](index.html?t=model) explains or predicts; a characterization system describes and compares. A model can *generate* the dimensions of a system, but the system itself carries no causal claims.
- **Not a definition**: [Definir](index.html?t=definir) fixes boundaries of one term; a system fixes the comparison space of many instances.

## Example

Public-organization comparison uses submodels (institutional position, governance, leadership, structure, authority, steering, operations, accountability, independence), each contributing one dimension with 3-5 categories. The same pattern applies to firms, research labs, or technical artifacts: fix dimensions once, profile every case the same way.
