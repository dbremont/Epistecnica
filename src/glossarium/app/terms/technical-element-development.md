# Technical Element Development

> **Technical Element Development** is the set of changes through which an element acquires its technical constitution and capabilities — and, in the realization chain, the work of building it out toward deployment.

> One term, two positions: the life-cycle phase and the chain step are the same work seen from the state side and from the activity side.

Development begins where design ends: the design says what the element should be, development makes an instance of it that can be tested, produced and deployed. It is iterative by nature — build, test, revise — and its characteristic output is not a document but a working instance plus the knowledge of how to make more.

The term is kept single deliberately. Splitting the state (development as a phase) from the activity (development as a chain step) would produce two names for one process and invite the question of which one a given case is in.
