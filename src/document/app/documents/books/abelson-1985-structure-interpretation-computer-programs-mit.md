**Problem Statement**

Given two approaches to structuring software systems:

1. **Single Data Structure + Many Functions** (100 functions over 1 data structure)
2. **Multiple Data Structures + Fewer Functions** (10 functions over 10 data structures)

**Decision Problem Representation**

- **Solution Space (Choices):**
    - $S_1$: Single data structure with many functions
    - $S_2$: Multiple specialized data structures with fewer functions
    - $S_2$: The middle.
- **Evaluation Model:**
    - Based on **principled design criteria**, including:
        1. **Expressiveness & Simplicity** – How well does the structure represent the problem?
        2. **Maintainability & Scalability** – How easy is it to extend or modify?
        3. **Performance & Efficiency** – Impact on memory usage, caching, and execution speed.
        4. **Reusability & Modularity** – Can the functions and data structures be reused across contexts?
        5. **Cognitive Tractability:** *Does this strategy, form, mechanism, and the programs it produces align well with human cognitive capabilities?*
- **Trade-Offs:**
    - **Universal Representation (Single Data Structure)** → More general, potentially more reusable but may lead to inefficient special cases.
    - **Specialized Representations (Multiple Data Structures)** → Optimized for specific use cases but may introduce fragmentation and complexity.

### Functions and the Processes they Generate

> A function is a pattern  for the local evolution of a  computational process.
> 

Recursion Type:

| **Type** | **Description** | **Canonical Case** |
| --- | --- | --- |
| **Tail Recursion** | Recursive call in tail position; no work after the call; optimizable to iteration. | Accumulator-based factorial; iterative list traversal. |
| **Linear Recursion** | Exactly one recursive call per activation (not necessarily tail). | Recursive factorial without accumulator. |
| **Tree Recursion** | Each call spawns *multiple* recursive calls; forms a recursion tree. | Fibonacci, generating a power set, permutations. |
| **Mutual Recursion** | Two or more functions call each other recursively. | `even(n)` ↔ `odd(n)` functions. |
| **Structural Recursion** | Recursion follows the inductive structure of input data; guarantees termination. | Recursing on lists, algebraic data types, AST traversal. |
| **Generative Recursion** | Recursion generates subproblems not structurally present in the input. | Quicksort partitioning; geometric recursion; fractals. |
| **Divide and Conquer** | Problem is split into smaller subproblems and combined. | Merge sort; Karatsuba multiplication; FFT. |
| **Corecursion (Co-Recursion)** | Builds potentially infinite structures; defines output by productive unfolding. | Infinite streams; lazy sequences; generators. |
| **Primitive Recursion** | Restricted form: recursive call on strictly smaller integer; ensures totality. | Addition/Multiplication defined from successor function. |
| **Higher-Order Recursion** | Recursion via higher-order combinators or fixpoints. | Y-combinator; recursive map/fold over higher-order functions. |
| **Memoized Recursion** | Recursion with caching to avoid recomputation; collapses exponential trees. | Fibonacci with memoization; DP top-down recursion. |
| **Parallel / Concurrent Recursion** | Independent recursive branches execute in parallel. | Parallel merge sort; fork-join divide-and-conquer. |
| **Backtracking Recursion** | Explores search space; unwinds on failure; tries alternatives. | DFS with constraint checking; N-Queens; SAT solvers. |
| **Continuation-Passing Recursion** | Recursion expressed by passing continuations; control is explicit. | CPS-converted evaluator; continuation-based interpreters. |
| **Metacircular Recursion** | System defined in terms of itself; recursion across meta-levels. | A Lisp interpreter written in Lisp (eval calling eval). |
